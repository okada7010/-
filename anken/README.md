# 案件管理ボード

案件を「状態」の列に並べて管理する、チーム共有のカンバンボードです（Google Apps Script ＋ スプレッドシート）。

- 列＝案件の状態（引合い → 見積 → 受注 → 設計・手配 → 施工中 → 完了）、カード＝案件
- カードに、担当者・納期・タスクの進捗（完了数／全体、％）を表示
- カードを開くと、案件の内容とタスク（担当者・期限・完了チェック）を編集できる
- 「一覧」表示で、全案件の状態・納期・進捗・次のタスクを表で確認できる
- 利用者はURLを開くだけ（Googleアカウント不要。共通パスワード＋名前の選択）

## ファイル

| ファイル | 内容 |
|---|---|
| `Code.gs` | サーバー側の処理（スプレッドシートの読み書き、ログイン） |
| `Index.html` | 画面 |
| `test/code.test.js` | `Code.gs` の確認用テスト（`node anken/test/code.test.js`） |

`Index.html` をブラウザで直接開くと、サンプルデータ入りの**デモ**として動きます（その端末のブラウザだけに保存。共有はされません）。

## 導入手順（管理者が1回だけ行う）

1. Googleスプレッドシートを新規作成する（名前の例：案件管理ボード）。部署共用のアカウントで作ると、担当者の異動に強い
2. 「拡張機能」→「Apps Script」を開く（必ずスプレッドシートから開く）
3. 最初からある `コード.gs` の中身を消し、`Code.gs` の内容を貼り付ける
4. 「＋」→「HTML」でファイルを追加し、名前を `Index` にして（大文字小文字も一致させる）、`Index.html` の内容を貼り付ける
5. 保存して、関数 `setup` を選び「実行」する。初回は権限の確認が出る（「詳細」→「（プロジェクト名）に移動」→「許可」）
6. スプレッドシートを再読み込みする。メニュー「案件管理」が出る
7. 「利用者」シートに、使う人の名前と「有効」＝`TRUE` を1行ずつ入力する
8. メニュー「案件管理」→「共通パスワードを設定」で、8文字以上のパスワードを設定する
9. Apps Script の「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
10. 表示されたURL（末尾が `/exec`）とパスワードを、利用者に別々の手段で伝える

### コマンド（clasp）で入れる方法

貼り付けの代わりに、Google 公式のコマンドツール clasp でコードを送れます。自分のPCで実行します（Node.js が必要）。

1. https://script.google.com/home/usersettings で「Google Apps Script API」をオンにする
2. `npm install -g @google/clasp`
3. `clasp login`（ブラウザが開くので、スプレッドシートを所有するアカウントで許可する）
4. `anken` フォルダで `clasp create --type sheets --parentId <スプレッドシートのID> --title 案件管理ボード --rootDir .`
   （IDは、スプレッドシートのURLの `/d/` と `/edit` の間の文字列）
5. `clasp push -f`（`Code.gs`・`Index.html`・`appsscript.json` が送られる）
6. `clasp deploy --description v1`（表示される ID のURL `https://script.google.com/macros/s/<ID>/exec` が公開URL）
7. 上の手順 5〜8（`setup` の実行と権限の許可、利用者の登録、パスワード設定）はスプレッドシート側で行う

コードを直したときは `clasp push -f` のあと `clasp deploy --deploymentId <ID> --description v2`（URLは変わらない）。
`.clasp.json`（スクリプトのID入り）は Git に入れない設定にしてある。

### コードを更新するとき

「デプロイ」→「デプロイを管理」→鉛筆アイコン→バージョン「新バージョン」→「デプロイ」。
「新しいデプロイ」を選ぶとURLが変わるので注意。

## スプレッドシートの構成

| シート | 内容 | 手で編集してよいか |
|---|---|---|
| 案件 | 1行1案件 | 原則アプリから。「アーカイブ」を `FALSE` に戻すと、ボードから外した案件が再表示される |
| タスク | 1行1タスク | 原則アプリから |
| 状態 | ボードの列（状態名・並び順） | **編集してよい**。行の追加・名前の変更・並び順の変更で列が変わる。並び順が最後の状態が「完了」扱い（納期超過の警告を出さない） |
| 利用者 | 名前・有効 | **編集してよい**。異動・退職者は行を消さず `FALSE` にする |

- 状態名を変えるときは、「案件」シートの「状態」列の同じ名前も置換する（一致しない案件は先頭の列に表示される）
- 見出し（1行目）の名前は変えない。列の順番は入れ替えてもよい

## 仕様メモ

- ほかの人の更新は最大60秒で反映（「更新」ボタンで即時）。リアルタイムではない
- 書き込みは1件ずつ処理する（LockService）。更新は行単位なので、別々の案件を同時に編集しても消えない。同じ案件を2人が同時に保存した場合は、後から保存した内容が残る
- 案件は削除せず「ボードから外す」（アーカイブ）。タスクの削除は行を消す
- スマホではカードのドラッグ移動はできない。カードを開いて「状態」を変更する
- パスワードはコードにもシートにも保存しない（スクリプト プロパティにソルト付きハッシュ）。ログインは30日有効。パスワードを変更すると全員が再ログインになる
- 名前は一覧から選ぶだけで、本人確認はしない（更新者の記録用）
- 「全員」公開のため、URLとパスワードを知っている人は誰でも見られる。機密性の高い情報（金額、個人情報など）は入れない運用を推奨。Googleの業務利用可否は社内ルールを確認すること

## 確認状況

- `Code.gs`：Node 上の簡易スプレッドシートでテスト済み（10件）。**Googleの実環境での動作は未確認**（公開後に、ログイン・登録・移動・2人同時の更新を確認する）
- `Index.html`：デモ動作で PC・スマホ幅の表示と操作を確認済み
